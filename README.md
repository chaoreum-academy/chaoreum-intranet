## v3 추가: 시험지 파일 → 정답, 종이 OMR 사진 제출

| 누가 | 어디서 | 무엇을 |
| --- | --- | --- |
| 강사 | OMR 과제 → 새 시험 만들기 (또는 시험 화면 「정답·문항정보 고치기」) | 「시험지 파일에서 정답 불러오기」로 **엑셀·PDF** 업로드 → 정답·문항 수·선택지 수·문항정보 칸이 채워짐 → 확인 후 저장 |
| 강사 | 시험 화면 → 「OMR 답안지 인쇄」 | 이 시험 전용 A4 답안지 인쇄 (모서리 표시·방향 막대·시험 확인 코드 포함) |
| 학생 | 시험 풀기 화면 → 「종이 OMR 답안지 사진으로 입력」 | 칠한 답안지를 찍으면 답이 화면 답안지에 채워짐. 흐리거나 두 개 칠한 문항은 주황색 「확인」 → 학생이 고른 뒤 제출 |

- **엑셀**: 「번호」「정답」 머리글이 있는 표(세로형) 또는 「번호」 줄 아래 「정답」 줄(가로형)을 찾아 바로 읽습니다. 「영역」「핵심 개념」「보완 방법」 열이 있으면 함께 읽습니다. AI 비용 없음.
- **PDF**(또는 표를 못 찾은 엑셀): Claude API가 파일 속 정답표를 읽습니다. 문제를 풀어서 정답을 만들지 않고, 정답표에 없는 문항은 비워 두고 알려 줍니다. Vercel 환경변수에 `ANTHROPIC_API_KEY`가 있어야 합니다. 파일은 4MB까지(Vercel 요청 한도).
- **사진 인식**은 학생 휴대폰 브라우저 안에서 처리합니다(서버 비용·외부 전송 없음). 채점은 지금처럼 DB 함수 `submit_exam`이 하므로 정답은 여전히 학생에게 전달되지 않습니다.
- 다른 시험의 답안지를 찍으면 「이 시험의 답안지가 아니에요」로 막습니다. 문항 수·선택지 수를 바꾼 시험은 답안지를 다시 인쇄하세요.
- 인식 규칙: `lib/omr/scan.ts` · 답안지 양식: `lib/omr/sheet.ts` (양식을 바꾸면 인식도 같이 바뀜).

## v3 추가: 수납·결제 (PG 연동 전)

왼쪽 메뉴 「운영 → 수납·결제」 (본사·실장·데스크, 강사에게는 안 보임).

- **반별 월 수강료** 입력 → **반 수강료 일괄 청구**: 고른 달에 다니는 재원생에게 청구서 생성 (다시 눌러도 중복 안 됨)
- **개별 청구**: 교재비·특강비 등, 할인·납기일·메모
- **수납 입력**: 현장 카드 단말기·현금·계좌이체, 나눠 내기(부분납), 환불, 잘못 입력한 기록 지우기 (모든 변경은 변경 기록에 남음)
- 월별 청구액·수납액·미수금·납기 지난 건수, 미납/완납/취소 필터
- **온라인 결제(PG)**: 아직 연결 전이라 화면에 「연동 준비 중」으로 표시. DB에는 `payments.method='online'`, `pg_provider`, `pg_tid` 칸을 미리 만들어 두어 PG 계약 후 같은 장부에 쌓입니다. 학부모는 RLS상 자녀 청구서를 읽을 수 있게 해 두었습니다(학부모 화면 결제 버튼은 PG 연동 때 추가).

DB 적용: SQL Editor에서 `supabase/migrations/0006_billing.sql` 실행 (또는 `full_schema.sql` 전체 다시 실행 — 기존 데이터 유지).

## 적용 (한 번에)

1. **DB**: Supabase SQL Editor에서 `supabase/full_schema.sql` 전체를 붙여넣고 Run. 처음이든 이미 일부 실행했든 상관없이 최신이 되고, 기존 데이터는 지워지지 않습니다.
2. **코드**: 깃허브 저장소에 이 폴더의 내용 전체를 올립니다(Add file → Upload files → 전부 끌어다 놓기 → Commit). Vercel이 자동 배포합니다.
3. **알리고**: 사이트 「연동 설정」에 키 4개 입력 → 「연결 확인」.
4. **학생**: 「학생 → 엑셀·명단 가져오기」 → 「계정 없는 학생 만들기」로 학생 로그인 계정 생성.
5. **알림톡**: 「알림톡」에 승인 템플릿 등록 → 내 번호로 테스트 → OMR 과제에서 템플릿·자동 발송 켜기.
6. (선택) `supabase/demo_seed.sql`로 샘플 데이터 확인, `demo_remove.sql`로 삭제.

| 검증 | 방법 | 결과 |

| 채점·코멘트·문자가 원본과 같은가 | 원본 Apps Script(`legacy/omr/Code.gs`)를 그대로 실행해 무작위 시험 3,000개 + 점수 환산 전 경우의 수를 새 코드와 비교 | 35,700건 중 불일치 0건 |

## 설치 (처음 한 번, 약 30분)

준비물: 구글 계정 또는 깃허브 계정. 비용은 두 서비스 모두 무료 요금제로 시작할 수 있습니다(학생 수가 늘면 유료 전환 검토).

### 1. 데이터베이스 만들기 — Supabase
1. https://supabase.com 가입 → **New project**
2. 이름 `chaoreum`, Region은 **Northeast Asia (Seoul)**, 데이터베이스 비밀번호는 따로 안전하게 보관
3. 왼쪽 **SQL Editor** → 아래 파일 내용을 차례로 붙여넣고 **Run**
   1. `supabase/migrations/0001_core.sql`
   2. `supabase/migrations/0002_omr.sql`
4. **Authentication → Sign In / Providers → Email** 에서 **Allow new users to sign up 끄기** (아무나 가입 못 하게. 계정은 플랫폼 안에서만 만듭니다)
5. **Authentication → Users → Add user** 로 실장님 이메일·비밀번호 생성 (Auto Confirm 체크)
6. `supabase/bootstrap_admin.sql` 의 이메일을 바꿔 SQL Editor에서 실행 → 실장님이 본사 관리자가 됩니다
7. **Project Settings → API** 에서 세 가지 값을 메모: Project URL, `anon` key, `service_role` key

### 2. 화면 배포 — Vercel
1. 이 폴더를 깃허브 저장소(비공개)로 올립니다
2. https://vercel.com → **Add New Project** → 저장소 선택
3. **Environment Variables** 에 `.env.example` 의 항목을 채워 넣습니다

| 이름 | 값 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key (**절대 외부 공유 금지**) |
| `NEXT_PUBLIC_APP_URL` | 배포 후 받은 주소 (예: `https://chaoreum.vercel.app`) |
| `STUDENT_EMAIL_DOMAIN` | `student.chaoreum.local` 그대로 두면 됨 |

4. **Deploy** → 몇 분 뒤 주소가 나옵니다

### 3. 처음 확인할 것 (권장 순서)
1. 실장님 계정으로 로그인 → 「계정」에서 테스트 강사 1명 생성
2. 「반」에서 반 하나 생성 → 강사 배정
3. 「학생」에서 맥가이 명단을 머리글째 복사해 붙여넣기 → 학생 1명 「계정 만들기」 (학번·임시 비밀번호가 화면에 표시됨)
4. 반 화면에서 그 학생 추가
5. 「OMR 시험」에서 기존 시트의 시험 하나를 정답·문항정보 그대로 붙여넣어 만들고 「시험 열기」
6. 휴대폰으로 학생 계정 로그인 → 답 선택 → 제출 → 점수·리포트 확인
7. 강사 화면에서 결과·학부모 문자 문안이 기존 시트와 같은지 비교

## 기존 시스템에서 바뀐 점

- 학번은 **앞자리 0을 채운 5자리**로 통일 (클리닉 규칙). OMR 시트는 0을 지웠으므로 옮길 때 자동 보정됩니다.
- 학생 로그인: 학번+이름 → **학번+비밀번호**. 리포트는 주소만으로 열리지 않고 로그인한 본인·학부모·담당 선생님만 봅니다.
- 강사 이름이 코드에 고정되어 강사마다 파일을 복사하던 구조 → 하나의 시스템에서 강사별로.
- 학부모 문자의 링크는 학부모 로그인 화면(`/p`)으로 연결됩니다.
- 재시험: 원본은 1회만 가능 → 시험마다 「재시험 허용」. 통계·순위·리포트는 원본처럼 1차 응시 기준.

## 앱으로 배포 (학생·학부모용 / 관리자용)

지금 버전은 휴대폰에서 주소로 열고 「홈 화면에 추가」하면 앱처럼 쓸 수 있습니다(PWA). 앱스토어 배포는 같은 화면을 감싸는 방식으로 나중에 추가합니다.

| 앱 | 시작 화면 | 방식 |
| --- | --- | --- |
| 차오름 (학생·학부모) | `/s`, `/p` | Capacitor로 감싸 앱스토어·플레이스토어 등록, 푸시 알림 추가 |
| 차오름 관리 (직원) | `/staff` | 같은 방식, 사내 배포 또는 스토어 비공개 |

화면 코드를 두 벌 만들지 않으므로, 웹에서 고친 내용이 두 앱에 그대로 반영됩니다. 스토어 등록에는 애플 개발자 계정(연 단위 유료)과 구글 플레이 개발자 계정이 필요합니다.

## 개발자용

```bash
npm install
cp .env.example .env.local   # 값 채우기
npm run dev                  # http://localhost:3000
npm run test:omr             # 원본 채점기와 비교 테스트
npm run typecheck
bash supabase/tests/run.sh   # 로컬 PostgreSQL에서 DB·권한 테스트 (postgres 사용자로)
```

폴더: `app/` 화면 · `lib/omr/` 채점 엔진(원본 이식) · `supabase/migrations/` DB와 권한 · `legacy/omr/` 원본 코드(비교 테스트용, 수정 금지)
